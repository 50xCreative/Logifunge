The Basics of Logifunge v3

Logifunge v3 treats source code as a grid. The instruction pointer starts at (0,0), moves right, and wraps around the edges. Direction changes turn a line of code into a path: programs can go around corners, travel vertically, and cross their own instructions.

Each cell is visited one at a time. Digits, literals, and strings put values on the stack; operators consume values; and the pointer advances after the instruction. A space does nothing. Execution ends at % or when the IDE's step limit is reached.

A first program

[65] = %

This pushes 65, prints the ASCII character A, and terminates.

The Stack and Postfix Programs

The data stack is last-in, first-out. A value is pushed onto the top and operators pop from the top. Therefore 23- means 2 minus 3. Empty pops return 0, which can be useful for default values but can also hide a missing input.

23- . %
after 2: [2]
after 3: [2, 3]
after -: [-1]
output: -1

Use : to duplicate a value, \ to swap the top pair, and $ to discard. Bracketed literals push multi-digit values directly.

Arithmetic

99*76*+ . %
output: 123

The same small operations that manipulate bits can also build ordinary integer values.

Movement and Decisions

> < ^ v point the instruction pointer right, left, up, or down. ? selects a random direction, and # skips the next cell. The horizontal conditional _ goes right for zero and left for nonzero. The vertical conditional ! goes down for zero and up for nonzero.

Named loops make the control flow easier to read. The closing marker pops a condition and jumps back to the opening marker if it is nonzero.

>5{[count]:.1-:}[count]$%

This prints 5 through 1. The duplicate keeps a copy for the loop test after the number is printed and decremented.

Logic Gates

Logic gates interpret zero as false and nonzero as true, then return 0 or 1. Binary gates pop their two operands from the stack.

CommandGateResult
&AND1 only when both inputs are true
|OR1 when either input is true
@XOR1 when exactly one input is true
~NOTInvert one input
N R XNAND, NOR, XNORInverted AND, OR, and XOR
00@. 01@. 10@. 11@. %
output: 0 1 1 0

For a half adder, duplicate the two inputs so XOR produces the sum and AND produces the carry:

11::@.\&.%
output: 0 1

Output, Pixels, and Grid Access

. prints a number and = prints ASCII. String mode pushes the character values between two quote instructions.

[72]=[105]=[33]=%
output: Hi!

Pixel output belongs to the IDE's canvas. , pops x, y, and a value, then writes the pixel. ' pops x and y and reads it back. Separate grid commands, g and p, read and modify the source grid itself.

Subroutines

Version 3 removes the ambiguity of v1 and v2. D[name] defines a routine and C[name] calls it. The routine ends at r. Definitions are skipped during ordinary flow, and return addresses use a separate stack.

1 C[inc] . %D[inc]1+r
output: 2

Names may contain any characters except ]. Definitions and calls can be written horizontally or vertically.

Packed Values and Memory

The parenthesis commands preserve a group of bits as one typed value. ( packs the requested number of stack values; ) unpacks them without needing the count again. The packed value carries its width with it.

00001 5 ( ) ..... %
output: 1 0 0 0 0

Memory uses a selected numeric pointer. M selects it, S stores the top value, and L loads the value.

5M 7S L . %
output: 7
