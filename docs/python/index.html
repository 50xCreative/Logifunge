What is this?

This isn't a LOGIFUNGE dialect or an esolang at all — it's plain Python 3, running via Pyodide, a build of CPython compiled to WebAssembly. It's included so the same editor and IDE chrome used for the esoteric languages can also double as an install-free Python scratchpad. Code you write here runs as real, unmodified Python — there's no custom grammar or instruction set to learn.

It plugs into the shared IDE the same way the lolcode engine does: you can Step through it one line at a time, watch the current scope's variables in the Stacks view, and see the line about to run highlighted in the editor. See "Stepping and variables" and "Using the IDE with Python" below for how that works.

Output

Anything written with print(), or anything sent to sys.stderr, appears in the Text output view in the order it happened. When you Step, the output grows one line of your program at a time.

print("Hello, World!")
output: Hello, World!

An unhandled exception doesn't stop the IDE — it prints a normal Python traceback (your own lines only) at the end of the output, the same as it would in a terminal, and the status bar shows the error.

Input

The IDE's top bar shows an Input field for this engine. Whatever you type there is split into lines before the program starts, and each call to input() pops the next line off the front of it. Once the field's lines are exhausted, a further input() call raises the normal EOFError — the same thing that happens when a real program's stdin runs dry.

name = input("name: ")
print(f"hello, {name}!")

Note that any prompt text passed to input() is not itself written to the output here, since there's nowhere for it to appear before the field is read — type your answer into Input ahead of time rather than waiting for a prompt to show up.

What's available

The Python standard library ships with Pyodide and works normally — math, json, re, itertools, and so on all import without any setup. Third-party packages are more limited: only pure-Python packages (and a handful of packages Pyodide ships precompiled to wasm) can be imported, and there's no network access or pip install from inside a running program — anything that needs to install a package or reach the network at runtime won't work here.

Loading time

The first time you press Run or Step on this page, your browser downloads the Pyodide runtime (roughly 10 MB) before your code executes — the status bar shows a loading message while this happens. The runtime is hosted on this site itself (under /pyodide/), not fetched from a third-party CDN; a CDN copy is only used as a fallback if the local files can't be loaded. Your browser caches it afterward, so every run after the first is fast.

Stepping and variables

Each Step advances the program by one line of your code, and the editor highlights the whole line that is about to run, the way a debugger like pdb does — so a line's effect shows up on the step after it. The Variables panel lists the current scope as name: value: the global variables at module level, or that call's local variables (under an in fname() heading) while inside a function. Modules, functions, and classes are left out, and long values are abbreviated.

total = 0
for n in range(3):
    total += n
print(total)

Only the lines you typed are stepped. A call into the standard library or another module counts as part of the line that made it.

If you don't want any of that, choose Instant in the Speed menu. Instant runs the program straight through at full CPython speed with no stepping and no Max Steps limit, then shows the final output and the final variables. It behaves like a normal Python runtime: input() still reads from the Input field, and top-level await works. The trade-off is that an infinite loop will freeze the tab, and Run can't be stopped once it starts.

Under the hood, the first time you press Run or Step the program is executed once, start to finish, while every line and its variables are recorded; Step and Run then replay that recording. Two things follow from this: input() reads from the Input field up front instead of waiting for you, and the program can't be paused partway — an infinite loop simply stops at the Max Steps limit with a "Step limit reached" error. Each run starts with a fresh namespace, so variables never carry over from one run to the next.

Using the IDE with Python

The IDE is the same one the other engines use, with a couple of things tailored for Python: the Pixel and Dual output views are hidden, since Python has no pixel output here — only Text and Stacks are shown, and the Stacks view shows a single Variables panel instead of the Data Stack + Memory pair. Because each step covers one line, the active-cell highlight spans the whole line being executed. Step, Run, Speed, Max Steps, the Input field, and syntax highlighting all work the same as on the other engines' pages, including Turbo mode. Python's Speed menu has one extra entry, Instant, described above.
