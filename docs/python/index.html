What is this?

This isn't a LOGIFUNGE dialect or an esolang at all — it's plain Python 3, running via Pyodide, a build of CPython compiled to WebAssembly. It's included so the same editor and IDE chrome used for the esoteric languages can also double as an install-free Python scratchpad. Code you write here runs as real, unmodified Python — there's no custom grammar or instruction set to learn.

Because a Python program executes as one opaque unit rather than one instruction at a time, this engine plugs into the shared IDE differently from v1-v6, brainfrick, and malbolge: there's no step debugger, no adjustable playback speed, and no 2D instruction pointer. See "Using the IDE with Python" below for exactly what's shown and hidden here.

Output

Anything written with print(), or anything sent to sys.stderr (including uncaught exception tracebacks), appears in the Text output view once the program finishes running.

print("Hello, World!")
output: Hello, World!

An unhandled exception doesn't stop the IDE — it prints a normal Python traceback to the output, the same as it would in a terminal, and the status bar shows the error.

Input

The IDE's top bar shows an Input field for this engine. Whatever you type there is split into lines before the program runs, and each call to input() pops the next line off the front of it. Once the field's lines are exhausted, a further input() call raises the normal EOFError — the same thing that happens when a real program's stdin runs dry.

name = input("name: ")
print(f"hello, {name}!")

Note that any prompt text passed to input() is not itself written to the output here, since there's nowhere for it to appear before the field is read — type your answer into Input ahead of time rather than waiting for a prompt to show up.

What's available

The Python standard library ships with Pyodide and works normally — math, json, re, itertools, and so on all import without any setup. Third-party packages are more limited: only pure-Python packages (and a handful of packages Pyodide ships precompiled to wasm) can be imported, and there's no network access or pip install from inside a running program — anything that needs to install a package or reach the network at runtime won't work here.

Loading time

The first time you press Run on this page, your browser downloads the Pyodide runtime (roughly 10 MB) before your code executes — the status bar shows a loading message while this happens. Your browser caches it afterward, so every run after the first is fast for the rest of the session.

Using the IDE with Python

Because Python here runs as one async unit rather than one instruction per step, several controls the other engines use don't apply and are hidden on this page: Step, the Speed and Max Steps controls, the direction indicator, and the Pixel/Dual output views. Run, Clear Output, the Input field, and syntax highlighting all work as usual. The Stacks view is still present but has nothing engine-specific to show, since Python's runtime state lives inside the wasm heap rather than in a shape this IDE can inspect.
