The Basics of Logifunge

Logifunge is a small, two-dimensional programming language in the tradition of Befunge. A program is a grid of characters rather than a line of statements. The instruction pointer, or IP, starts at the upper-left cell and initially travels from left to right.

Each step reads one cell, performs its instruction, and advances the IP in its current direction. The IP can travel right, left, up, or down, and it wraps when it reaches the edge of the grid. Spaces are empty cells: they do nothing, but the IP still travels through them.

The v6 IDE lets you run a program at different speeds, execute one step at a time, and view text output, pixel output, both together in dual view, or the data and memory stacks. An optional syntax-highlighting mode colors the editor by instruction category. Programs stop with %, when an error occurs, or when the step limit is reached.

A first program

The program below pushes the number 65, prints it as an ASCII character, and stops.

[65] = %
output: A

Numbers are written in brackets when they have more than one digit. Thus [65] is the multi-bit number 65, while the characters 6 and 5 push two separate values.

The Stack

Logifunge uses one last-in, first-out (LIFO) stack. Putting a value on it is called pushing; taking the top value off is called popping. Most instructions treat an empty stack leniently: if there's nothing to pop, they receive 0 rather than causing an underflow. A few instructions instead require a specific number of values up front — indexed swaps, pixel writes, and modulo among them — and report an error if the stack is too shallow, since quietly substituting 0 there would more likely hide a bug than help.

Arithmetic and gates use postfix notation, and two-value operators combine their operands in the order the values were pushed, not the order they're popped. The first value written ends up beneath the second, so 23- pushes 2 and then 3, and computes 2 minus 3, not 3 minus 2. In a longer program, it helps to write the stack after each instruction:

23- . %
stack:       []
after 2:     [2]
after 3:     [2, 3]
after -:     [-1]
after .:     []       output: -1

Three commands rearrange the stack without doing arithmetic: : duplicates the top value, \ swaps the top two values, and $ pops a value without using it.

Inspecting and rearranging the stack

Two further commands work on the stack as a whole rather than on individual values. l pushes the stack's current length — the count is taken before this push, so an empty stack pushes 0, and a stack with three values on it pushes 3. This is useful for loops that should run once per remaining value, or for checking there's enough on the stack before an operation that needs it. U reverses the entire stack in place, which is handy when values were pushed in one order but are needed in the opposite order.

1 2 3 l . %
output: 3

Here three values are pushed, then l reports the depth (3) at that point, and . prints it.

1 2 3 U . . . %
output: 1 2 3

Pushing 1, 2, and 3 leaves the stack as [1, 2, 3] with 3 on top. U reverses it to [3, 2, 1], so the three pops that follow print 1, then 2, then 3 — the original push order restored.

W swaps two stack positions by index: index 0 is the top value, index 1 is the value below it, and so on. It pops two indexes and reports an error if either is out of bounds.

Building larger values

Digits push values from 0 through 9. A bracketed literal pushes a larger integer directly:

[123] . %

Bracketed literals are convenient, but arithmetic is useful when a value is being calculated. The following computes 123 from small digits, just as the classic Befunge examples build larger numbers from 9s and 7s.

99*76*+ . %

A bracketed literal is read in whichever direction the IP is actually traveling, starting from whichever bracket it lands on first. Reading forward over [12] pushes 12, as expected. But entering the same literal moving left — landing on the closing ] first — reads the digits in the order they're encountered, which is reversed: a leftward pass over [12] pushes 21, not 12. This only matters for literals a program deliberately walks backward into; written and read normally, left to right, a literal behaves exactly as it looks.

There are four direct movement instructions. A direction remains active until another direction instruction changes it.

The horizontal conditional _ pops a value. It travels right when the value is 0 and left when it is nonzero. The vertical conditional ! travels down for 0 and up for a nonzero value.

Named loops

A conditional combined with a turn can make a loop by hand, but Logifunge also has a dedicated pair of loop markers. {[name] marks the top of a named loop; it consumes nothing and just marks a position. }[name] pops one value — nonzero jumps back to the matching {[name], and zero continues forward past it.

>5{[count]:.1-:}[count]$%
output: 5 4 3 2 1

Names may contain any characters except ], and a marker and its [name] may be written horizontally (the bracket immediately to the right) or vertically (the bracket directly below, with the name and closing bracket continuing downward).

For loops

Where a named loop requires the program to track and pop its own counter, a for loop tracks the count internally. ([name] pops a count N and runs the body N times; if N is zero or negative, the body is skipped entirely and execution resumes just past the matching )[name]. )[name] pops nothing — unlike }[name] — the interpreter itself remembers how many iterations remain, and jumps back to ([name] until the count is exhausted.

G pushes the current for loop's iteration index: 0 on the first pass, N−1 on the last. Using G outside an active for loop is an error. With nested for loops, G refers to the innermost one.

5([i]G.)[i]%
output: 0 1 2 3 4

Here the loop runs 5 times. Each pass pushes and prints its own index via G, with nothing left to pop at the closing marker.

Logic Gates

Logifunge treats 0 as false and a nonzero value as true for logic operations. The gates return 0 or 1, making them useful for decisions and digital circuits.

CommandOperationStack behavior
&ANDpop a, pop b, push a AND b
|ORpop a, pop b, push a OR b
@XORpop a, pop b, push a XOR b
NNANDthe inverse of AND
RNORthe inverse of OR
XXNORthe inverse of XOR
~NOTpop a, push the one-bit inverse of a

Here is the complete XOR truth table. Each pair is consumed by @, then . prints the result.

00@.  01@.  10@.  11@. %
output: 0 1 1 0

A half adder demonstrates why duplication matters. Starting with two 1 bits, one copy is sent to XOR for the sum and another to AND for the carry.

11::@.\&.%
output: 0 1

NAND alone is universal: any other gate can be built from it. AND, for instance, is NAND applied twice to the same pair.

11N:N.%
output: 1

Input, Output, and Pixels

Text output is appended to the IDE's output pane. . pops and prints a decimal number; = pops and prints its ASCII character. String mode, entered with ", pushes the character value of every cell until the next quote.

[72]=[105]=[33]=%
output: Hi!

Pixels are values in the IDE's configurable grid. , pops a value, y, and x and writes that value at (x,y). ' pops y and x and pushes the pixel currently stored there. Coordinates outside the visible grid are ignored for drawing.

001, 111, %
writes pixels (0,0) and (1,1)

Grid access is separate from pixel output. g pops y then x and pushes the character currently in grid cell (x,y). p pops y, x, and value, then changes that cell. This is how Logifunge programs can inspect and modify their own code.

Self-modifying code

The tricky part of p is timing: it can overwrite a cell the IP hasn't reached yet, so the instruction that eventually runs there isn't the one visible in the source. Laid out by position, this program does exactly that:

position:   0    1    2    3    4    5    6    7    8
character:  "    5    "    6    0    p    2    .    %

Cells 0–2 use string mode to push the character code for 5 (53). Cells 3–4 push 6 and 0 — the coordinates of the 2 waiting at position 6. When the IP reaches p at position 5, it pops those three values (y, then x, then the value) and overwrites position (6, 0) — the 2 — with a 5.

By the time the IP steps forward onto position 6, that cell no longer holds the 2 printed in the source; it holds the 5 that p just wrote. So the program prints 5, not 2:

"5"60p2.%
output: 5

Subroutines

Named subroutines give a program reusable pieces without overloading the ordinary stack commands. Define one with D[name]; its body ends at r. Normal program flow skips over the definition, including nested definitions inside it. Call it with C[name]; the return address is saved separately from the data stack.

1 C[inc] . %D[inc]1+r
output: 2

The definition above is skipped while the main program runs. The call jumps to D[inc], pushes 1, adds it to the caller's value, and returns. Names may contain any characters except ]. Definitions, calls, and both loop markers can each be written horizontally or vertically — whichever orientation is used, the IP resumes immediately after the closing bracket in that same direction.

Memory

Memory is a sparse collection of numbered cells, independent of the data stack. M pops an index and selects it as the active memory pointer. S stores the top stack value there without removing it. L loads the selected value onto the stack; an unset cell loads as 0.

5M 7S L . %
output: 7

Exponents

P pops an exponent, pops a base, and pushes the base raised to that power, flooring the result if it isn't a whole number. Q pops a root index, pops a value, and pushes the floor of the integer nth root. Taking an even-numbered root of a negative value is an error, since the result isn't real.

2[10]P.[27]3Q.%
output: 1024 3

The example computes 210 with P, then the cube root of 27 with Q.

Absolute Value, Modulo, and Sign

A pops a value and pushes its absolute value. s pops a value and pushes its sign: -1, 0, or 1.

38-A.%
output: 5
38-s.%
output: -1

m pops two values and pushes the remainder, following the same push-order convention as the other two-value operators: the first value pushed is the dividend and the second is the divisor. Unlike A and s, m requires two values already on the stack and reports an error rather than substituting 0 if the stack is too shallow.

73m.%
output: 1

Elbow Redirect

E pops a value. A nonzero value leaves the current direction untouched — the IP keeps going straight. A zero turns the IP 90° clockwise: right becomes down, down becomes left, left becomes up, and up becomes right.

90E
  .
  %
output: 9

The IP starts moving right, pushes 9 and then 0, and reaches E heading right. Popping the 0 turns it to travel downward, where it lands on . and prints the 9 left on the stack, then reaches % below that.

Using the v6 IDE

The v6 IDE is an execution and inspection environment for Logifunge programs. The editor is on the left and the selected view is on the right. You can edit the source at any time, then run it again or step through it from the beginning.

Execution controls

The status line reports states such as Ready, Running, Done, and errors. During stepping, the direction indicator shows the current IP direction and the editor highlights the active cell.

Output views

Choose one of four views. Text shows printed numbers and characters, Pixel shows the pixel canvas, and Dual shows both at once. Stacks replaces the output with an inspector for the data stack and sparse memory.

Inspecting large stacks

The stack inspector is designed for programs that leave thousands or millions of values behind. The global Value search filters values in both lists, while Index searches indexes in both lists. The filters can be combined.

Each panel also has its own range field and ordering menu. Enter an inclusive range such as 0:10. Negative values clamp to 0, values beyond the available maximum clamp to the last index, and reversed ranges are normalized. For example, -99:5 becomes 0 through 5, and 0:999999999999 ends at the collection's maximum index.

Only a bounded number of rows are rendered at once. This keeps the interface usable even when the underlying stack contains one million values. The inspector remains scrollable, and searches are briefly debounced while you type.

Important differences from Befunge-93

Logifunge borrows the two-dimensional instruction pointer and postfix stack model, but it is not a Befunge-93 implementation. In Logifunge, @ is XOR, not the end instruction; % ends a program, not modulo; & | ~ N R X are logic gates; and subroutines use explicit D[name] and C[name] markers rather than overloading :. Logifunge also adds pixels, sparse memory, and a browser-based step debugger.

Changes since v5

This is a breaking change from v5: ( and ) no longer pack and unpack bit-values. They are now the for-loop markers described above, and there is no packing operator in v6. Existing v5 programs that use ( or ) for packing will need to be rewritten.

New in v6: P and Q for exponents and integer roots, E for elbow-turn redirects, the ([name] )[name] G for-loop family alongside the existing named loops, and A, m, and s for absolute value, modulo, and sign. The IDE also adds a SYNTAX toggle for editor highlighting.
