What is brainfrick?

brainfrick is a standard Brainfuck implementation running inside the LOGIFUNGE shared IDE. It isn't a LOGIFUNGE dialect — the grammar is plain, classic Brainfuck — it's here because the same engine interface the v1..v6 Befunge-style interpreters use turned out to fit Brainfuck too, so it plugs into the same editor, step debugger, and output views with no changes to any of that shared code.

The one real difference from the v1-v6 engines: the instruction pointer here does not move in two dimensions. There's no up, down, or direction-changing instruction. The IP simply reads the source left to right, wrapping to the next line, the way you'd read a page of text.

Commands

CommandEffect
>Move the tape pointer right.
<Move the tape pointer left.
+Increment the current cell, wrapping 255 to 0.
-Decrement the current cell, wrapping 0 to 255.
.Output the current cell as an ASCII character.
,Read one character from Input into the current cell. See Input below.
[If the current cell is 0, jump forward to just past the matching ].
]If the current cell is nonzero, jump back to the matching [.

Every other character — letters, digits, punctuation, whitespace — is a comment. It's skipped with no effect, the same way a blank cell does nothing in the v1-v6 engines.

++++++++[>++++++++<-]>+.
output: A

The loop above runs 8 times, adding 8 to the next cell each pass (64 total), then a trailing + brings it to 65 — A in ASCII — which . prints.

The Tape

Brainfuck has one piece of state: a tape of cells, addressed by an integer index, with a single read/write head. There is no separate data stack. The tape is sparse and unbounded in both directions — moving the pointer left of index 0 with < is perfectly legal, unlike a fixed-size array.

Because there's no data stack to inspect, the Stacks view for this engine shows only one panel, Tape, instead of the Data Stack + Memory pair the v1-v6 engines show. The * marker in that panel marks the cell the pointer is currently on.

Input

Brainfuck's , command reads one character at a time from an input source. The IDE's top bar shows an Input field for this engine — type or paste text into it before pressing Run or Step, and each , pulls the next character's ASCII code off the front of it. Once the field is exhausted, further , reads store 0 in the current cell (the common "EOF is zero" convention).

,[.,]
Input: hi
output: hi

This reads and immediately echoes each character until input runs out: , reads one character, the loop body prints it and reads the next, and the loop ends once a read comes back 0.

Using the IDE with brainfrick

The IDE is the same one the v1-v6 engines use, with a few things tailored for Brainfuck specifically: the Pixel and Dual output views are hidden, since Brainfuck has no pixel output — only Text and Stacks are shown. The direction indicator stays fixed since the IP never changes direction. Step, Run, Speed, Max Steps, and syntax highlighting all work the same as on the other engines' pages.
