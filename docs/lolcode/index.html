What is lolcode?

lolcode is a JavaScript reimplementation of LOLCODE — the LOLcat-speak esolang — running inside the LOGIFUNGE shared IDE. It isn't a LOGIFUNGE dialect; the grammar follows the reference C implementation, lci, closely enough to run its own style of example programs (declarations, conditionals, switches, loops, and functions including recursion).

Unlike v1-v6, brainfrick, and malbolge — which step through source one character at a time — LOLCODE's vocabulary is made of multi-character words (VISIBLE, SUM, OF, MKAY, ...), so this engine's step consumes one lexical token per step instead: one word, number, string, or comment. The active-cell highlight in the editor spans the whole token being executed rather than a single character.

IT and expressions

Every scope has an implicit variable, IT, which holds the result of the last bare expression statement. This matters for control flow: a condition is written as its own statement (setting IT), and the following O RLY? / WTF? reads it.

BOTH SAEM AGE AN 20
O RLY?
    YA RLY
        VISIBLE "TWENTY!"
    NO WAI
        VISIBLE "NOT TWENTY"
OIC

Prefix math and boolean operators work the same way as arguments: SUM OF a AN b, DIFF OF, PRODUKT OF, QUOSHUNT OF, MOD OF, BIGGR OF, SMALLR OF for arithmetic; BOTH OF, EITHER OF, WON OF, NOT, ALL OF ... MKAY, ANY OF ... MKAY for booleans; BOTH SAEM and DIFFRINT for equality; SMOOSH ... MKAY to concatenate strings; and MAEK expr A TYPE to cast without mutating the original.

Loops, switches, and functions

IM IN YR label [UPPIN/NERFIN YR var] [TIL/WILE expr] ... IM OUTTA YR label is a loop with an optional per-iteration counter and an optional exit condition, checked before each pass; GTFO breaks out early.

IM IN YR LOOP UPPIN YR COUNT TIL BOTH SAEM COUNT AN 5
    VISIBLE COUNT
IM OUTTA YR LOOP
output: 0 1 2 3 4 (one per line)

WTF? ... OMG literal ... OMGWTF ... OIC is a switch on IT, with C-style fallthrough between OMG cases until a GTFO.

HOW IZ I name [YR param [AN YR param ...]] ... IF U SAY SO defines a function; FOUND YR expr returns a value. Calls use I IZ name [YR arg [AN YR arg ...]] MKAY, and recursion works normally since each call gets its own scope.

HOW IZ I FACTORIAL YR N
    BOTH SAEM N AN 0
    O RLY?
        YA RLY
            FOUND YR 1
        NO WAI
            FOUND YR PRODUKT OF N AN I IZ FACTORIAL YR DIFF OF N AN 1 MKAY
    OIC
IF U SAY SO
VISIBLE I IZ FACTORIAL YR 5 MKAY
output: 120

Input

The IDE's top bar shows an Input field for this engine. Whatever you type there is split into lines before the program runs, and each GIMMEH pops the next line off the front of it as a YARN (string). Once the field's lines are exhausted, further GIMMEH calls read an empty string.

What's not supported

Arrays (BUKKIT), module bindings (CAN HAS?), and concurrent threading are not implemented — this covers the core imperative language: variables, arithmetic and boolean prefix operators, string concatenation and casts, conditionals, switches, loops, and functions with recursion.

Using the IDE with lolcode

The IDE is the same one the other engines use, with a couple of things tailored for lolcode specifically: the Pixel and Dual output views are hidden, since LOLCODE has no pixel output — only Text and Stacks are shown, and the Stacks view shows a single Variables panel (the current scope's variables, with IT listed first) instead of the Data Stack + Memory pair. Because each step consumes one word or token rather than one character, the active-cell highlight in the editor spans the whole token being executed. Step, Run, Speed, Max Steps, the Input field, and syntax highlighting all work the same as on the other engines' pages.
