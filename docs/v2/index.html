The Basics of Logifunge v2

Logifunge v2 runs a character grid with a moving instruction pointer. It starts at the upper-left, travels right, and wraps at the edges. A space is a blank instruction, not a stop. Direction commands let a program cross its own path and form loops.

Execution is deliberately small: one cell is read, one instruction is performed, and the pointer advances. Use the IDE's STEP control when learning a program; the stack and output change one instruction at a time.

A first program

[65] = %

The literal pushes 65, = prints its ASCII character, and % ends execution.

Stack Calculations

The stack is last-in, first-out: the value pushed most recently is popped first. Digits and bracketed numbers push values; operators pop their operands and push one result. If an operator needs a value that isn't there, it treats the missing value as 0 rather than erroring — convenient, but worth remembering if an output looks off.

99*76*+ . %
stack after +: [123]
output: 123

Order matters because two-value operators combine their operands in the order they were pushed, not the order they're popped: 23- pushes 2, then 3, and computes 2 minus 3, not 3 minus 2. : duplicates the top value, \ swaps the top two, and $ discards the top value without using it.

0-9 [n]Push a digit or integer literal.

Movement and Loops

> < ^ v set the direction and ? chooses randomly. # skips the next cell. The conditionals _ and ! pop a value and choose a direction based on whether it is zero — _ branches horizontally, ! vertically. (| is a different instruction: the OR gate, covered below.)

A named loop is a useful way to repeat a calculation. The opening marker records a location; the closing marker pops a value and jumps back only when that value is nonzero.

>5{[count]:.1-:}[count]$%

Logic Gates

Logic gates consume stack values as booleans and produce 0 or 1. Here is the XOR truth table in the same compact style used by the classic Befunge examples:

00@. 01@. 10@. 11@. %
output: 0 1 1 0
CommandGate
&AND
|OR
~NOT
@XOR
N R XNAND, NOR, XNOR

Duplicate an input before sending it to two gates. For example, 11::@.\&.% prints the XOR sum and AND carry of a half adder.

Text, Pixels, and Grid Access

. prints a number, = prints ASCII, and string mode pushes character codes between quotes. Pixel write , consumes x, y, and a value; pixel read ' consumes x and y and pushes the stored value. The IDE displays these writes in its pixel canvas.

[72]=[105]=[33]=%

g reads a program-grid cell at x,y, while p changes one. This makes self-inspection and self-modification possible.

Self-modifying code

Because p can write ahead of the IP, the instruction that actually runs at a position can differ from what's printed in the source. Here's the layout of a small example:

position:   0    1    2    3    4    5    6    7    8
character:  "    5    "    6    0    p    2    .    %

String mode (cells 0–2) pushes the character code for 5. Cells 3–4 push the coordinates 6 and 0, pointing at the 2 sitting at position 6. p pops those and overwrites that cell with 5 before the IP gets there, so the program prints 5 instead of 2:

"5"60p2.%
output: 5

Subroutines

Like v1, v2 overloads :. A bare colon duplicates the top stack value; a colon followed by a name, :[name], defines a routine that ends at r. Call it with ;[name]. Definitions are skipped during normal flow and calls use a separate return stack.

1 ;[inc] . % :[inc]1+r

This syntax is replaced by explicit markers in v3.
